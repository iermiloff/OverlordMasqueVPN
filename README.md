# OverlordMasque

![Status](https://img.shields.io/badge/status-beta-orange)
![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-blue)
![Python](https://img.shields.io/badge/python-3.10%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

**OverlordMasque** — десктопный клиент для протокола [MASQUE (CONNECT-IP, RFC 9484)](https://datatracker.ietf.org/doc/rfc9484/) на базе ядра [Xray-core](https://github.com/XTLS/Xray-core) и драйвера [Wintun](https://www.wintun.net/).

Трафик MASQUE неотличим от обычного HTTPS/HTTP-3, что делает его значительно устойчивее к DPI по сравнению с VLESS, Trojan и XHTTP.

## ✨ Возможности

- **MASQUE-туннель** поверх HTTP/3 (QUIC) или HTTP/2 (TCP) с автоматическим fallback при блокировке UDP.
- **Встроенная маршрутизация Windows** — маршруты настраиваются самим Xray (`autoSystemRoutingTable`), без хрупких PowerShell-команд.
- **Защита от утечек** через `autoSystemWfpBlockLeak`: блокировка DNS и IPv6 за пределами туннеля на уровне Windows Filtering Platform.
- **Профили подключений**: сохранение нескольких конфигураций (сервер/порт/логин/пароль) и быстрое переключение между ними.
- **Автосохранение последней сессии** — при следующем запуске поля уже заполнены.
- **Резолв домена до старта Xray** — обходит блокировку системного DNS, которая возникает из-за WFP-правил.
- **Корректная поддержка буфера обмена** во всех полях ввода, включая не-английские раскладки (Ctrl+C/V/X/A и контекстное меню).
- **Экспорт логов** сессии в текстовый файл для диагностики.
- **Тёмная тема** в стиле Overlord (CustomTkinter).
- **UAC-элевация** — клиент корректно запрашивает права администратора, необходимые для создания TUN-адаптера и настройки маршрутов.

## 📋 Требования

### Для пользователей

- **Windows 10 (версия 1809 и новее) или Windows 11** — из-за зависимости от Wintun и WFP.
- **Права администратора** — обязательны для создания TUN-адаптера и изменения таблицы маршрутизации.
- **Сервер с поддержкой MASQUE**, например [3x-ui](https://github.com/MHSanaei/3x-ui) v3.10.0+ или Xray-core v26.x с настроенным MASQUE-инбаундом.

### Для сборки

- [Python 3.10+](https://www.python.org/downloads/)
- [PyInstaller](https://pyinstaller.org/) (`pip install pyinstaller`)
- [Inno Setup](https://jrsoftware.org/isdl.php) — опционально, для создания установщика
- Файлы `xray.exe` (v26.x+ с поддержкой MASQUE) и `wintun.dll` (v0.14.1) — **не входят в репозиторий**, скачиваются отдельно (см. ниже).

## 🚀 Установка (для пользователей)

1. Скачайте последний релиз из раздела [Releases](../../releases).
2. Запустите `OverlordMasque_Setup.exe` и следуйте инструкциям мастера установки.
3. При первом запуске примите запрос UAC — без прав администратора клиент не сможет создать TUN-адаптер.
4. Введите реквизиты подключения, выданные вашим провайдером (домен сервера, порт, имя пользователя, пароль).
5. Нажмите **АКТИВИРОВАТЬ VPN** и дождитесь статуса «ТУННЕЛЬ УСПЕШНО АКТИВИРОВАН».

> ⚠️ **Антивирусы.** Клиент не подписан код-сертификатом, поэтому некоторые антивирусы (особенно Windows Defender) могут показывать предупреждения. Это ложные срабатывания, типичные для всех неподписанных сетевых утилит. При сборке используется `--onedir --noupx` — эти флаги снижают количество ложных срабатываний, но не устраняют их полностью. Если хотите быть уверены в безопасности — соберите клиент самостоятельно из исходников.

## 🛠 Сборка из исходников

### 1. Клонирование репозитория

```bash
git clone https://github.com/iermiloff/OverlordMasqueVPN.git
cd OverlordMasqueVPN

```

### 2. Установка зависимостей

```bash

pip install customtkinter pyinstaller

```

### 3. Подготовка ресурсов

Скачайте и положите в корень проекта следующие файлы:
```
Файл	Откуда взять	Версия
xray.exe	XTLS/Xray-core Releases	v26.x или новее (обязательно с поддержкой MASQUE)
wintun.dll	wintun.net	v0.14.1, архитектура amd64
icon.ico	На ваш выбор	256×256, ICO
```
    ❗ Важно: MASQUE появился в Xray относительно недавно (v26.x). Более старые версии не распознают протокол masque в конфиге и завершатся с ошибкой. Убедитесь, что скачиваете актуальный релиз.

### 4. Сборка .exe через PyInstaller

```bash

pyinstaller --onedir --windowed --noupx --clean --uac-admin ^
  --icon=icon.ico ^
  --add-data "xray.exe;." ^
  --add-data "wintun.dll;." ^
  --add-data "icon.ico;." ^
  --name "OverlordMasque" client.py

```

Ключевые флаги:

    --onedir — сборка в папку (а не в один файл). Снижает ложные срабатывания антивирусов, потому что .exe не самораспаковывается в %TEMP% при каждом запуске.

    --windowed — скрывает консольное окно.

    --noupx — отключает UPX-упаковку (ещё один триггер эвристики антивирусов).

    --uac-admin — встраивает манифест с requireAdministrator, UAC-запрос появляется до запуска кода.

Готовая сборка появится в dist\OverlordMasque\.

### 5. Создание установщика (опционально)

Если у вас установлен Inno Setup, сохраните скрипт installer_script.iss:
ini

```
[Setup]
AppName=OverlordMasque
AppVersion=1.0
DefaultDirName={autopf}\OverlordMasque
DefaultGroupName=OverlordMasque
UninstallDisplayIcon={app}\OverlordMasque.exe
Compression=lzma2
SolidCompression=yes
OutputDir=installer_output
OutputBaseFilename=OverlordMasque_Setup
PrivilegesRequired=admin

[Files]
Source: "dist\OverlordMasque\*"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs createallsubdirs

[Icons]
Name: "{group}\OverlordMasque"; Filename: "{app}\OverlordMasque.exe"
Name: "{autodesktop}\OverlordMasque"; Filename: "{app}\OverlordMasque.exe"; Tasks: desktopicon

[Tasks]
Name: "desktopicon"; Description: "Создать ярлык на рабочем столе"; GroupDescription: "Дополнительные задачи:"

[Run]
Filename: "{app}\OverlordMasque.exe"; Description: "Запустить OverlordMasque"; Flags: nowait postinstall skipifsilent

```

Затем нажмите F9 (Build → Compile). Установщик появится в installer_output\OverlordMasque_Setup.exe.

## 🖥 Использование

    Заполните поля:

        Домен сервера — доменное имя MASQUE-сервера (например, vpn.example.com). Клиент сам резолвит его в IP, чтобы обойти блокировку DNS со стороны WFP.

        Порт — порт MASQUE-инбаунда (обычно 443).

        Имя пользователя / Пароль — реквизиты MASQUE-клиента на сервере.

    Нажмите «АКТИВИРОВАТЬ VPN». В правой панели начнут появляться логи ядра Xray. Туннель обычно поднимается за 1–3 секунды.

    Проверьте подключение — откройте любой сайт. Весь трафик должен идти через туннель.

    Сохраните профиль кнопкой 💾 — в следующий раз можно выбрать его из выпадающего списка и не вводить данные заново.

    Сохранить логи — если что-то не работает, кнопка 📄 запишет лог в текстовый файл, который можно приложить к issue.


Все пользовательские файлы — профили, настройки и временный конфиг Xray — хранятся в %APPDATA%\OverlordMasque\

```
%APPDATA%\OverlordMasque\
├── user_saved_config.json    # Последняя сессия
├── saved_profiles.json        # Именованные профили
└── config_temp.json           # Временный конфиг Xray (удаляется при отключении)
```

Папка создаётся автоматически при первом запуске. В Program Files клиент ничего не пишет — это позволяет устанавливать его в системную директорию без прав на запись во время работы.

## Часть 3: Серверная сторона, структура, безопасность, ограничения, контрибьютинг
🌐 Настройка серверной стороны

Для работы клиента нужен Xray-сервер с MASQUE-инбаундом. Пример конфига (фрагмент), совместимого с 3x-ui:
```
{
  "listen": "",
  "port": 443,
  "protocol": "masque",
  "tag": "in-443-masque",
  "settings": {
    "address": ["10.14.0.1/24", "fd14::1/64"]
  },
  "sniffing": {
    "enabled": true,
    "destOverride": ["http", "tls", "quic"]
  },
  "streamSettings": {
    "network": "masque",
    "masqueSettings": {
      "path": "/.well-known/masque/ip/*/*/"
    },
    "security": "tls",
    "tlsSettings": {
      "serverName": "vpn.example.com",
      "certificates": [
        {
          "certificateFile": "/root/cert/vpn.example.com/certfull.crt",
          "keyFile": "/root/cert/vpn.example.com/certificate.key"
        }
      ],
      "alpn": ["h3"]
    }
  }
}
```

Ключевые моменты:

    alpn: ["h3"] — сервер принимает HTTP/3 (QUIC, UDP). Клиент с alpn: ["h3", "h2"] выберет h3, если сеть пользователя не блокирует UDP.

    Если хотите поддержать клиентов в сетях с блокировкой UDP — добавьте "h2" в alpn сервера и используйте alpn: ["h3", "h2"] в клиенте.

    masqueSettings.path должен совпадать с тем, что используется в клиенте (по умолчанию /.well-known/masque/ip/{target}/{ipproto}/).

    Пользователи создаются через панель 3x-ui (или её API) как обычные клиенты MASQUE-инбаунда. В клиенте вводятся email и password этого клиента.

## 🔒 Безопасность и приватность

    Пароли в профилях хранятся в JSON-файлах в %APPDATA% с простой base64-обфускацией (префикс b64:). Это не шифрование, а лишь сокрытие от случайного взгляда. Если вам нужна реальная защита — используйте менеджер паролей и не сохраняйте профили на общих машинах.

    Клиент не собирает телеметрию и не отправляет никаких данных, кроме самого VPN-трафика на указанный сервер.

    Все сетевые соединения идут только на сервер, указанный в полях ввода.

    Логи ядра остаются локально в памяти и сохраняются в файл только по явной команде пользователя.

## ⚠️ Известные ограничения

    Только Windows. Клиент использует Wintun и Windows Filtering Platform, которые есть только в Windows. Linux/macOS не поддерживаются.

    Требуется Xray v26.x+. Более старые версии не поддерживают протокол MASQUE. Проверьте версию ядра перед сборкой.

    UDP должен быть разрешён на стороне пользователя для HTTP/3. Если UDP заблокирован, клиент автоматически переключится на HTTP/2 (TCP), но это работает только если сервер тоже поддерживает h2 в alpn.

    Антивирусы могут ругаться. См. раздел Установка. Решение — подпись кода код-сертификатом (в планах).

    Нет автоматического обновления. Клиент не проверяет наличие новых версий. Следите за релизами на GitHub.

    Реквизиты не выдаются автоматически. Клиент не умеет получать конфиги от сервера — их нужно вводить вручную. Интеграция с Telegram-ботом и централизованным контроллером — в разработке.

## 🤝 Участие в разработке

Pull request'ы и issue приветствуются. Если нашли баг — приложите, пожалуйста:

    Версию клиента (видна в заголовке окна или в Properties файла).

    Версию Windows.

    Логи из правой панели (кнопка 📄 Сохранить логи).

    Описание шагов для воспроизведения.

Перед созданием PR с крупными изменениями откройте issue для обсуждения подхода.
Что приветствуется в первую очередь

    Интеграция с контроллером конфигов (см. раздел «Известные ограничения»).

    Подпись кода — это уменьшит количество ложных срабатываний антивирусов.

    Локализация интерфейса (английский, другие языки).

    Тесты для generate_tun_config и валидации портов.

    Улучшение fallback-логики (сейчас срабатывает по ключевым словам в логах, что не всегда идеально).
